## 0. 总则

### 0.1 优先级与门槛

| 级别 | 含义 | 发布门槛 |
|---|---|---|
| P0 | 没有就不算能用；崩溃/数据错误/红线 | **100% PASS**（允许 ≤1 项 BLOCKED，但须 Lead 书面豁免并说明替代证据） |
| P1 | 应该有；影响完成度 | ≥90% PASS |
| P2 | 可以以后做 | 只记录，不阻断 |

缺陷分级：S1 崩溃/数据丢失/触碰红线；S2 P0 功能失败；S3 P1 失败；S4 视觉/文案。发布要求：无 S1/S2。

### 0.2 判定规则

- PASS：判定标准的全部条件满足，证据齐全。
- FAIL：任一条件不满足；必须附实际输出/截图与预期对比。
- BLOCKED：环境或依赖缺失导致无法验证；必须写清缺什么、谁负责、替代证据。
- 涉及「自动验收」的清理/卸载删除路径，一律只做 dry-run 与守护测试；真实执行路径由人工在独立测试机验证，不计入自动门禁。

### 0.3 测试环境与初始状态

1. 被测 App：/Users/ksullivan/Code/deepseek/otter2/build/Otter.app（由 scripts/build.sh 生成）。
2. 首次启动类用例前清空偏好：执行 defaults delete com.ottermac.app（会删除 Otter 自身偏好，测试后允许重建；不影响其他应用）。
3. 每个用例开始前：pkill -f 'Otter.app/Contents/MacOS/Otter'，等待 1s。
4. 证据目录：/tmp/otter2-evidence/{用例ID}/，至少保存：
   - run.log（启动/运行日志）
   - 截图（涉及界面）
   - footprint.txt / cpu.txt（非功能）
   - 期望 vs 实际说明（README.md，中文）
5. 深浅色切换后必须还原系统外观。

### 0.4 红线（违反即 S1）

- 不对真实用户数据执行清理：clean 只用 dry-run（preview）。
- 不对真实应用执行卸载/删除：卸载删除路径只做取消、受保护、不存在等守护测试；真实 trash 仅人工用自制测试 app，且事后从废纸篓恢复。
- 不修改 otter/ 旧项目；不 git commit；不联网。
- 不绕过二次确认；不直接调用 FileManager 删除真实路径。

## 1. 执行准备（所有用例通用）

~~~bash
cd /Users/ksullivan/Code/deepseek/otter2

# 1) 构建（已加锁，可并发）
./scripts/build.sh
# 预期：退出码 0，stderr 无 error，末行 built: .../build/Otter.app

# 2) 清理旧进程
pkill -f 'Otter.app/Contents/MacOS/Otter' 2>/dev/null || true
sleep 1

# 3) 启动（按用例选择钩子）
OTTER_SHOW_HUD=1 ./build/Otter.app/Contents/MacOS/Otter > /tmp/o2.log 2>&1 &
sleep 2
PID=$(pgrep -f 'Otter.app/Contents/MacOS/Otter' | head -1)
echo "PID=$PID"

# 4) 窗口列表（格式：pid | windowid | owner | title | x,y WxH）
/tmp/winlist | grep -i otter

# 5) 截图（WID 来自上一步第 2 列）
screencapture -l "$WID" -x -o /tmp/otter2-evidence/HD-01/hud.png

# 6) 内存 footprint
/tmp/footprint "$PID"

# 7) 结束
pkill -f 'Otter.app/Contents/MacOS/Otter' 2>/dev/null || true
~~~

说明：
- 窗口识别：主窗口标题为 Otter、尺寸 960×660（最小 760×520）；HUD 为 Otter 进程的 400×520 无边框窗口（标题可能为空）。
- 菜单栏条目不在 /tmp/winlist 中，用全屏截图裁剪顶部右侧区域验证：
  screencapture -x -R 1400,0,400,40 /tmp/otter2-evidence/MB-01/menubar.png
- 深色：osascript -e 'tell application "System Events" to tell appearance preferences to set dark mode to true'（测试后设回 false）。
- 首选自动断言钩子见 SPEC 附录 B；钩子未实现时用截图人审 + 代码走查，并标记风险。

## 7. 验收执行顺序与报告

### 7.1 每次构建的最小门禁（Smoke，约 10 分钟）

5. 空闲 footprint/CPU（NF-01、NF-04）。
6. 无网络、无 Dock（NF-10、NF-11）。
7. 深浅色截图（NF-09）。
8. 服务未就绪不崩溃（HD-12、CL-10）。

### 7.2 发布前完整验收

按第 2–6 章全量执行；输出报告：
- 汇总表：总用例数、PASS/FAIL/BLOCKED、按优先级分列。

- 豁免清单：BLOCKED 项 + Lead 书面原因。
- 结论：可发布 / 不可发布。
